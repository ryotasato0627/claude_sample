# 実装計画: Frontend 画面

`docs/spec/requirements.md` の機能要件(第3章)を満たす Frontend 画面を実装する。

PR の分割は `docs/development/pull-request.md` の「PR Granularity」、コミットの分割は `.claude/skills/commit-strategy/SKILL.md` に従う。

## 前提

- Backend の API はすべて実装済み。OpenAPI(`api/openapi.yaml`)と生成コード(`frontend/src/api/schema.gen.ts`)は変更しない。
- 現在のユーザーを返す API は無い。ログイン応答(`LoginResponse`)の `user` を、トークンと一緒に保存して使う。
- 自分のロールは `Project.role` から取得する。
- ログアウトは API を呼ばず、保存したトークンと user を削除する(トークンの失効はスコープ外)。

## 決定事項

| 項目 | 決定 |
| ---- | ---- |
| ルーティング | `react-router` |
| UI | Pico CSS(`@picocss/pico`)。クラスを付けずに HTML 要素へスタイルが当たるため、画面のコード量を増やさない |
| Issue | 現時点で Issue は無い。ブランチ名は `feature/frontend-<機能>` とし、`Refs:` は付けない |

## PR 計画

| # | PR タイトル | 含む機能 | 見込み行数 | 依存先 |
| - | ----------- | -------- | ---------- | ------ |
| 1 | `feat: ユーザー登録・ログイン画面を追加` | 登録、ログイン、ログアウト、未ログイン時のリダイレクト | 約 400 | - |
| 2 | `feat: プロジェクト一覧・作成画面を追加` | 所属プロジェクトの一覧、作成 | 約 250 | #1 |
| 3 | `feat: プロジェクト詳細・編集・削除を追加` | 詳細の表示、編集・削除(owner のみ) | 約 300 | #2 |
| 4 | `feat: メンバー管理画面を追加` | 一覧、追加、ロール変更、削除 | 約 350 | #3 |
| 5 | `feat: Task 一覧・作成を追加` | プロジェクト内の Task 一覧(絞り込み・ページネーション)、作成 | 約 350 | #3 |
| 6 | `feat: Task 詳細・編集・削除を追加` | 詳細、タイトル・説明・ステータス・担当者の変更、削除 | 約 400 | #4, #5 |
| 7 | `feat: コメント機能を追加` | 一覧、投稿、編集・削除 | 約 300 | #6 |
| 8 | `feat: Task 検索画面を追加` | キーワード・ステータス・担当者・プロジェクトでの検索 | 約 300 | #5 |

- 見込み行数はテストを含み、生成ファイルと lock ファイルを含まない概算。PR 作成前に計測する。
- マージ順は 1 → 2 → 3 → (4, 5) → 6 → 7。#8 は #5 のマージ後ならいつでもよい。#4 と #5 は並行して作業できる。
- `docs/spec/requirements.md` §11 の実装状況は、各 PR で自分の機能の分だけ更新する。
- #1 が 400 行を超えた場合: ルーティング・認証状態の管理とログイン画面はまとめて初めて動作を確認できるため分割せず、PR 本文の「備考」に理由を書く。
- #6 が 400 行を超えた場合: 「削除」を別の PR に分ける。

## コミット計画

各コミットの前に、コンテナ内で `typecheck` / `lint` / `test` を実行する。

### #1 ユーザー登録・ログイン

1. `feat: ログイン・ログアウトを追加` — `react-router` と Pico CSS の追加、`auth/`(トークンと user の保存、未ログイン時のリダイレクト)、`api/errors.ts`(エラーを表示用に変換)、`pages/Login.tsx`、`App.tsx` の書き換えとテスト。既存の `App.test.tsx` もここで直す
2. `feat: ユーザー登録画面を追加` — `pages/Register.tsx` とテスト
3. `docs: 認証画面の実装状況を更新`

当初はルーティングとログイン画面を別コミットにする計画だったが、ログイン画面の無いルーティングは未ログイン時のリダイレクト先が存在せず動作しないため、機能単位(ログイン・ログアウト / 登録)で分けた。

### #2 プロジェクト一覧・作成

1. `feat: プロジェクト一覧・作成画面を追加` — `api/projects.ts`(TanStack Query の hooks)、`pages/Projects.tsx` とテスト
2. `docs: 実装状況を更新`

### #3 プロジェクト詳細・編集・削除

1. `feat: ロール判定ヘルパーを追加` — `auth/permissions.ts`(権限マトリクスの全組み合わせをテスト)
2. `feat: プロジェクト詳細・編集・削除を追加` — owner 以外には編集・削除を表示しないこと、404 の表示をテスト
3. `docs: 実装状況を更新`

### #4 メンバー管理

1. `feat: メンバー管理画面を追加` — 未登録メールでの 422、重複時の 409、最後の owner を外すときの 409 をテスト
2. `docs: 実装状況を更新`

### #5 Task 一覧・作成

1. `feat: Task 一覧を追加` — ステータス・担当者での絞り込み、ページネーション
2. `feat: Task 作成を追加` — viewer には作成ボタンを表示しないことをテスト
3. `docs: 実装状況を更新`

### #6 Task 詳細・編集・削除

1. `feat: Task 詳細とタイトル・説明の編集を追加`
2. `feat: ステータス・担当者の変更を追加` — 担当者の選択肢は #4 のメンバー一覧の hooks を使う。担当を外すときは `assigneeId: null` を明示して送る
3. `feat: Task 削除を追加`(owner のみ)
4. `docs: 実装状況を更新`

### #7 コメント

1. `feat: コメントの一覧・投稿を追加`
2. `feat: コメントの編集・削除を追加` — owner は全件、member は自分のコメントのみ編集・削除できることをテスト
3. `docs: 実装状況を更新`

### #8 Task 検索

1. `feat: Task 検索画面を追加` — 絞り込みの選択肢に #2 のプロジェクト一覧、結果の表示に #5 の Task 一覧の表示部品を使う
2. `docs: 実装状況を更新`
